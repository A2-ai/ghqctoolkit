### Correctness

- [ ] The code does what its documentation and the issue description say it does
- [ ] Edge cases and missing or malformed input are handled
- [ ] Error paths fail loudly rather than silently producing wrong results

### Readability

- [ ] Naming is consistent with the rest of the project
- [ ] Complex logic is either simplified or explained
- [ ] Dead code, debug statements, and commented-out blocks are removed

### Verification

- [ ] Tests cover the new behavior, including at least one failure case
- [ ] The full test suite passes on the reviewed commit
- [ ] Changes are scoped to the issue; unrelated edits are absent
